1. 整体流程

curses.wrapper(main)
  → map / 地图
  → mirror / 镜像 → shift
  → drawer / 抽屉 → order + badges
  → circuit / 电路（可选 optional）→ sequence
  → gate / 门禁 → radio + committed branch
  → Relay / Corridor / Shaft → escaped
  → Archive → hidden story / 隐藏剧情
  • 主程序负责流程，interface 负责通用终端交互，expedition 负责资源规则，四个 decipher 文件实现关卡，finale 实现最终挑战，savegame 与 archive 分别保存当前局和跨局收藏。
  • 第三关可跳过，但会影响第四关供电模式和最终挑战。

1.1 建议阅读顺序

  1. 先看 main.py。 找到 PUZZLES 和主循环，理解“地图选择 → 调用关卡 → 根据返回值更新进度”。
  2. 再看前两关。 它们展示最简单的模式：读取答案、检查答案、写入线索。
  3. 接着看 expedition.py 和 interface.py。 分别理解资源扣除和界面绘制。
  4. 最后看移动关卡、结局和存档。 先理解状态字段，再读改变这些字段的方法。

1.2 用一次操作理解程序

以第一关输入正确答案为例：

  1. main.py 调用 decipher_1.main(screen, clues)。
  2. 关卡通过 read_command() 获取文字；check_command() 判断答案。
  3. 答案正确后执行 clues['shift'] = 7，把偏移量交给后续关卡。
  4. 关卡返回 True，主程序才把对应的 solved 标记改为 True。

1.3 第四关：两个顺序、三种对象

容易混淆的内容中文解释
箱子 A、B地图中能推动的物体，放在 a、b 上供电
徽章 A、C、V第二关得到的数字，只用于算密码
终端顺序决定先去哪个终端，例如 2 → 3 → 1
终端密码决定在某个终端输入哪个数字
房间 3 的供电完成第三关获得，允许使用正常供电路线
gate.powered当前所需的箱子是否仍压在对应机关上

计算示例： 假设徽章 A=10、C=50、V=80，offset=7，则终端 1 的密码是 17，终端 2 是 43，终端 3 是 94。如果当前顺序是 2 → 3 → 1， 就先去终端 2 输入 43，再去 3 输入 94，最后去 1 输入 17。 这是解释规则的例子，每局应使用笔记中的实际数字与顺序。

设备与按键： 地图中的 O 是无线电，F 是警报开关。 移动到设备旁后按键盘 E 才会操作。地图上的 E 则表示出口；走到出口和按 E 键不是一回事。

1.4 三种返回值不能混用

接口返回值含义
read_command()文本或 None提交的答案或取消
关卡 main()True 或 False是否完成该关

32def wrap(message, width):
33    """Word-wrap ASCII text without importing another library."""
34    result = []
35    remaining = str(message)
36    while len(remaining) > width:
37        split = remaining.rfind(' ', 0, width + 1)
38        if split <= 0:
39            split = width
40        result.append(remaining[:split])
41        remaining = remaining[split:].lstrip()
42    result.append(remaining)
43    return result
  • 循环寻找宽度内最后一个空格换行；没有空格时按宽度切开，最后加入剩余文字。
  • 意义：让英文提示按词换行，长单词也能显示。
  • 调用方应传入正宽度。

  1. Start with main.py. Follow map selection, the puzzle call, and the completion result.

1.2 Follow one action

For a correct room-one answer: the controller calls the room, the input helper reads the command, the room stores offset 7 in the shared dictionary, and its True result tells the controller to mark the room complete. Storing a clue and marking a room complete are two separate operations.

5. Boundaries to explain accurately

  • Room three is optional, not a prerequisite for room four.
  • Not every class is purely nonvisual: EnergyCircuit and GatePuzzle focus on state, while finale classes also provide draw methods.
  • Seeds vary selected values, orders, and node positions; room terrain is not randomly generated.
  • Cells are the run-wide failure budget; circuit charge and shaft energy are local action budgets.
  • Re-entry recreates the circuit and gate, but retains the finale object.
  • Validation is neither anti-cheat nor a full reachability proof; direct writes do not guarantee an old save survives interruption.
  • The course’s “subclass” field refers to the class section; the three finale classes are not inheritance-based subclasses of a custom base.
